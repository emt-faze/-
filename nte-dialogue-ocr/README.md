# 异环 · 对话文字识别

用于 Windows PC 版《异环》的本地对话识别工具。当前版本为 **v5.0.0 开发预览版**，默认通过 WGC 获取游戏窗口，用 RapidOCR 的 PP-OCRv6 small 显示首次结果、medium 复核同一条台词。

## 下载与安装

在 [GitHub Releases](https://github.com/emt-faze/-/releases/tag/nte-ocr-v5.0.0) 下载：

| 文件 | 内容 | 首次安装 |
| --- | --- | --- |
| `nte-dialogue-ocr-v5.0.0-windows-with-models.zip` | 源码、脚本、4 个 OCR 模型 | 安装 Python 依赖，校验已有模型 |
| `nte-dialogue-ocr-v5.0.0-source.zip` | 源码、脚本、模型来源与校验值 | 安装依赖并下载约 170 MB 模型文件 |
| `SHA256SUMS.txt` | 两个压缩包的 SHA-256 | 可用于检查下载是否完整 |

两个压缩包均需要 **Windows 10/11 和 Python 3.12（64 位）**。它们不是独立 EXE，也不包含 Python 解释器或虚拟环境。带模型包可省去 OCR 模型下载，首次安装依赖仍需要网络。

1. 从 [Python 官网](https://www.python.org/downloads/windows/) 安装 Python 3.12（64 位），安装时启用 Python Launcher 或加入 PATH。
2. 解压到可写的普通文件夹，进入 `nte-dialogue-ocr`。
3. 双击 `setup.cmd`。脚本会创建本目录的 `.venv`、安装固定版本依赖，校验或下载模型，并在缺少配置时创建 `config.json`。
4. 安装完成后双击 `start-ocr.cmd`。

安装脚本保留已有 `config.json` 和虚拟环境；下载模型时，只有文件长度及 SHA-256 都正确才替换目标文件。网络失败后可重新运行安装脚本。

## 第一次使用

1. 将游戏停在一段完整对话上，暂时不要翻页。
2. 在工具中点击“自动打开游戏并连接”。游戏已经运行时，会连接现有窗口。
3. 若未找到官方启动器，点击“选择启动器”，选择本机的 `NTEGame.exe`、`NTEGlobalGame.exe` 或 `NTETWGame.exe`。
4. 在截图中点击“框选正文”，包含全部正文行和标点；再点击“框选角色名”，单独框住人名。
5. 点击“启动识别”。确认首句文字、原图和复核记录正常保存后，再推进剧情。
6. 点击“停止识别”结束采集。

示例配置中的 1920×1080 区域只用于提供初始值，**发布包默认未校准**。不同分辨率、画面比例、UI 缩放和字幕布局需要重新框选。包中没有携带开发者的游戏安装路径或校准截图。

`start-game-and-ocr.cmd` 会打开工具并发起自动连接。完整流程是：官方启动器 → 开始游戏 → 等待标题 → 确认中下方“进入游戏”文字 → 点击 → 用游戏内画面确认进入。

操作官方启动器需要管理员权限时，会使用 Windows 的正常授权提示；取消授权会停止该操作。登录、更新或验证提示需要在官方界面完成。程序不会把加载画面当成已进入游戏，也不会无限重试点击。

## 截图与后台识别

- 默认 WGC，计划每秒采样 5 次，预览每秒更新 2 次，只保留最新帧。
- 默认允许 WGC 在游戏未最小化时后台识别；最小化时暂停。
- MSS、PrintWindow 保留为手动选择项，不会在失败后自动切换。
- MSS 按桌面可见区域取图，需要游戏保持前台且文字区域没有遮挡。
- 截图、识别和保存由工作线程执行，预览窗口不会置顶遮住正文。

## 如何理解识别状态

- **候选**：首次结果已经显示，等待复核。
- **已复核**：两次正文一致、得分达到 0.90，并且未发现裁剪或未解释的漏覆盖笔画。
- **待核对**：两次不一致、得分不足、疑似截断，或文字框旁仍有未确认的笔画。

“已复核”不代表人工确认无误。两个模型属于同一模型家族，可能同时识别错误。

复核绑定原台词 ID，修改同一条记录；出现分歧时保留首次正文，不自动用复核结果替换。人名单独处理，低分或短暂缺失的人名不会重复输出正文。

v5 针对文字框漏掉单独笔画的问题，增加原图覆盖检查和扩展范围整行识别；同时保留原模型文字、检测框、笔画位置及追加识别结果。数字、否定词和专有名词没有词典式自动替换，去重也不使用模糊文本相似度。

## 当前限制

当前校准针对固定剧情对话框。行走字幕会向上移动，低位过场字幕也可能超出原范围，这两类布局尚未完成适配。

已知材料上的离线回归结果：最近一段固定对话首次正文 22/22 完全正确，复核 21/22；另有 3 页行走字幕未覆盖。前一段 29 页固定对话首次 28/29、复核正文 29/29。它们均已用于开发，不能替代未见台词验收，也不能保证其他场景准确率。

完整验证说明见 [docs/VALIDATION.md](docs/VALIDATION.md)。

## 记录与配置

| 位置 | 内容 |
| --- | --- |
| `config.example.json` | 可公开的默认配置，首次使用必须校准 |
| `config.json` | 本机实际配置，包括游戏路径及文字区域 |
| `records/日期/会话编号/dialogue.txt` | 易读的当前识别记录 |
| 同目录 `dialogue.jsonl`、`revisions.jsonl` | 当前版本及完整修订历史 |
| 同目录 `images/` | 正文、人名等原始证据图 |
| 同目录 `session.json`、`presentation.jsonl` | 采样、资源占用和界面更新耗时 |
| `validation/` | 本机截图和启动、验收检查结果 |

OCR 在本机运行，不需要 API 密钥。安装时会从 Python 包源和固定的模型地址下载文件；识别过程不上传游戏截图。

个人配置、运行记录、截图、日志、模型大文件和虚拟环境已加入 `.gitignore`。升级前保留自己的 `config.json`、`records/` 和 `assets/ocr-v6/`。

## 开发与检查

在本目录打开 PowerShell：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -p "test_*.py"
.\.venv\Scripts\python.exe scripts\download_models.py --verify-only
.\.venv\Scripts\python.exe app.py --list
```

前两项不会操作游戏。窗口列举需要在正常交互桌面运行。

公开包不包含开发者的真实剧情记录，因此依赖这些图像的检查会明确跳过。`validation/README.md` 会保留测试所需目录。新增的打包检查验证配置优先级、损坏模型下载不会覆盖旧文件，以及完整模型无需再次联网。

主要模块：`app.py` 负责界面与流程，`capture_windows.py` / `capture_session.py` 负责窗口及截图，`ocr_engines.py` / `ocr_core.py` 负责识别及复核，`frame_gate.py` 负责稳定画面判断，`game_launch.py` / `game_scene.py` 负责启动流程和进入场景判断。
